# 发布 ZIP 前，先让 Codex 做一次隐私体检

很多人第一次上传 GitHub 时，会直接把整个文件夹压缩后发布。真正容易泄露信息的通常不是主程序，而是被一起打包进去的 `.env`、凭据文件、测试报告、邮箱地址和个人目录。

本期方案提供了一个本地只读检查器：[查看完整方案](../../solutions/2026-09-08-audit-zip-privacy/README.md)。它不会解压或执行 ZIP 中的文件，也不会联网；发现疑似秘密时，只在报告中记录风险类型，不复制秘密原文。

## 适合谁

- 准备把工具上传到 GitHub 的新手
- 想把项目 ZIP 发给别人，但不确定里面有没有个人信息的人
- 希望让 Codex 先检查、再由自己决定是否发布的人

## 可以直接复制给 Codex

```text
请只读检查我指定的 ZIP，不解压、不执行、不修改原文件。使用方案中的 Audit-ZipPrivacy.ps1 扫描，但不要显示任何秘密原文。请把结果分成：可以继续人工复核、发现风险暂缓上传、扫描不完整需要人工处理。最后说明已检查和未检查的范围；没有命中规则不能表述为绝对安全。
```

完整提示词在 [PROMPT.md](../../solutions/2026-09-08-audit-zip-privacy/PROMPT.md)。

## 怎么操作

1. 下载或复制本期方案目录。
2. 把 ZIP 路径填进完整提示词。
3. 让 Codex 运行只读扫描并解释 JSON 报告。
4. 如果发现 `High` 或 `Review`，暂缓上传并人工检查相应文件。
5. 清理后重新制作 ZIP，再运行一次扫描。

## 正确结果是什么

- `Safe`：规则范围内没有发现问题，仍需人工查看文件列表。
- `Review`：发现敏感文件名、疑似秘密、邮箱、个人路径或未扫描内容。
- `Error`：ZIP 无法读取，当前不能给出结论。

## 安全提醒

OpenAI 官方说明，Codex 的沙盒限制可访问范围，审批策略决定敏感操作是否需要暂停确认。处理陌生压缩包时，使用工作空间范围和只读要求能降低误操作风险：[智能体审批与安全](https://learn.chatgpt.com/zh-Hans/docs/agent-approvals-security)。

这个检查器不能识别所有隐私信息，也不能代替杀毒、版权或法律审查。它的价值是把最常见、最容易遗漏的风险先筛出来，并明确告诉你哪些内容没有被证明安全。
