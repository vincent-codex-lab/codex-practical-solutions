# 用 Codex 在上传 GitHub 前检查 ZIP 是否泄露隐私

## 今天解决什么问题

准备把 ZIP 发到 GitHub、网盘或群聊前，先让 Codex 对压缩包做一次只读检查，找出疑似令牌、私钥、邮箱、个人目录和敏感配置文件。检查器不会解压文件，也不会把匹配到的秘密值写进报告。

## 适合谁

- 第一次发布 GitHub 项目的普通用户
- 经常分享脚本、配置或项目压缩包的人
- 使用 Windows PowerShell 5.1 或更新版本的用户

预计用时约 10 分钟。扫描本身不需要联网，也不会修改 ZIP。

## 开始前准备

1. 把待检查 ZIP 放到一个你能找到的位置。
2. 在 Codex 中打开本方案目录。
3. 如果压缩包包含真实业务资料，先使用只读或请求审批权限，并明确要求不展示秘密值。

OpenAI 官方资料说明，Codex 的沙盒和审批策略共同决定它能访问与修改的范围；处理陌生文件时应优先限制在当前工作空间并审查敏感操作：[智能体审批与安全](https://learn.chatgpt.com/zh-Hans/docs/agent-approvals-security)。

## 操作步骤

### 方法一：直接让 Codex 完成

复制 [PROMPT.md](PROMPT.md) 的完整提示词，把其中的 ZIP 路径替换成自己的文件，然后发送给 Codex。Codex 会先运行只读扫描，再解释脱敏报告。

### 方法二：自己运行检查器

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Audit-ZipPrivacy.ps1 -ZipPath "待检查文件.zip" -ReportPath ".\privacy-report.json"
```

退出码含义：

- `0`：规则范围内没有发现问题
- `10`：发现需要人工检查的项目，不建议立即公开
- `2`：文件不存在、格式错误或无法读取

## 预期结果

程序输出 JSON 报告，其中包括扫描文件数、跳过文件数和发现项。发现项只记录规则名称、严重程度和脱敏后的压缩包内部路径，不记录实际匹配值。

`Safe` 只表示当前规则没有命中，不等于证明压缩包绝对安全。公开前仍应检查文件列表和来源。

## 失败时如何处理

- 显示 `Error`：确认文件是有效 ZIP，并检查是否被其他程序独占。
- 显示 `ContentNotScanned`：文件超过安全扫描上限，应单独审查该文件或在确认内存足够后调整上限。
- 显示 `SensitiveFileName`：打开对应文件确认是否只有示例值；不要因为文件名看起来正常就忽略内容检查。
- 出现任何 `High`：先停止上传，删除或替换秘密信息，然后重新扫描。

## 隐私与安全

- 检查器完全在本机运行，不进行网络请求。
- 不解压 ZIP，因此不会执行其中的程序，也不会产生路径穿越写入。
- 报告不包含匹配到的令牌、邮箱或密码原文。
- 不要把真实秘密粘贴进聊天来询问“这是不是密钥”。
- 检查完成后仍要人工确认许可证、版权和业务数据是否允许公开。

## 能力边界

该工具使用规则匹配，只能发现已知格式或明显特征。经过编码、加密、拆分、存放在二进制文件中的秘密可能无法发现；姓名、地址、照片和文档内容也需要人工判断。它不是杀毒软件、漏洞扫描器或法律审核工具。
